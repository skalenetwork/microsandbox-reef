Overview · 02

Four questions before an agent goes live.

Security and platform teams need clear answers. reef turns each one into a setting you can review.

QuestionWith reef
What can it reach?
Only the domains in its role. Opening the whole internet is an explicit setting.
Which credentials can it use?
Keys declared in the role stay on the host and work only toward one named service.
Who approved its setup?
Roles are files in git. Protect the branch and every change is reviewed.
Who can use it?
A single sign-on proxy in front of it decides who reaches it. A shell needs an SSH certificate matching its owner.

Overview · 09

Built on microsandbox.

Isolation comes from microsandbox, an open-source microVM runtime under the Apache-2.0 license. We chose it because it combines the four properties agents need in one runtime.

ContainersTraditional VMsmicrosandbox
Own kernel per agentShared host kernelYesYes
Runs standard container imagesYesNot directlyYes
Blocks unapproved domains outside the agentNeeds extra toolingNeeds extra toolingBuilt in
Keeps API keys out of the agentNeeds extra toolingNeeds extra toolingBuilt in

Checked, not assumed

Several runtimes advertise similar features. In our August 2026 review, each alternative fell short on something reef needs.

reef adds the policy layer

Role files, reviewed versions, fleets, durable agent records and one console across hosts.

Deep dive · 01

One binary, one host, one microVM per agent.

reef is a command-line tool with no daemon. Each command updates the agent record, compares it with the running VM and applies the difference.

Deep dive · 02

Three controls, enforced outside the agent.

None of them depends on the agent's own configuration or good behavior.

Network allowlist

Domains only, blocked by default, checked at DNS by the runtime. Opening the internet takes an explicit *.

egress = ["openrouter.ai"]

Credentials stay on the host

A secret is a reference bound to one domain. The agent sees a placeholder; the runtime swaps in the value on the way out.

# real-VM test
$ echo [$FAKE_KEY]
[$MSB_FAKE_KEY]

Loopback is off limits

Agent ports bind to the host's loopback, which no agent can reach, whatever its role allows.

# reef ui
gateway=http://openclaw.localhost:19004

Declaring a secret turns on TLS interception for the whole VM, and the shipped roles then skip browser certificate checks. What an egress allowlist costs

Deep dive · 04

Browser access through your single sign-on.

reef exposes agent ports on localhost only. In the documented setup, Cloudflare Access handles sign-in and cloudflared connects out from the host, so no inbound port is opened.

A request

  1. The browser opens the agent's hostname, which resolves to Cloudflare.
  2. Access signs the person in with your identity provider.
  3. The request travels down the tunnel cloudflared opened from the host. cloudflared checks the signed token.
  4. cloudflared forwards it to the agent's port on 127.0.0.1.
  5. The agent opens a session under the person's email.

Setup, in this order

  1. Add hostnames to the fleet file and apply it.
  2. Create one Access application per hostname.
  3. Configure the tunnel with one rule per hostname.
  4. Run cloudflared under its own unprivileged user.
  5. Point DNS at the tunnel last.
  6. Verify from another machine: expect a sign-in redirect, never a page.

Cloudflare is one option. Any single sign-on proxy that is the only path to the port works. Shell access uses SSH certificates checked against the agent's owner. Setup guide

Deep dive · 05

Clawbits and reef communicate through git.

Clawbits never connects to your servers. It writes agent files to your private repository. Each host pulls every 30 seconds and pushes its status back.

From click to first message

  1. A member picks a role and a machine in Clawbits.
  2. Clawbits commits an agent file with a one-time signup token, valid for 7 days.
  3. The host pulls the change within 30 seconds and applies it.
  4. reef starts the agent's microVM.
  5. The host pushes its status. Clawbits shows the agent running.
  6. The agent redeems its token and keeps its permanent key on its own volume.
  7. The agent checks in. Clawbits marks it available.
  8. The member says hi in chat.

Who can reach what

Clawbits
One private repository, through a token you scope to it
Reef host
The same repository, through its own deploy key
Agent
Outbound only, to the public internet its role allows
Inbound
Nothing connects in to the host

Deep dive · 06

Where reef stands.

Available today

  • Open source, MIT license, release 0.14
  • Linux servers with KVM and glibc 2.39 or newer, and Apple Silicon Macs
  • Roles for OpenClaw and Hermes
  • Clawbits integration, shipped in Clawbits 1.0

Known limits

  • Secret values are stored unencrypted on the host
  • No HTTP API yet: operated through the CLI and console
  • A role upgrade replaces the agent's system disk; volumes persist
  • The microsandbox runtime is pre-1.0, pinned to an exact version

Next

  • Remove the runtime's second copy of secret values
  • Under consideration: a GitHub App instead of a personal access token
  • Under consideration: GitHub webhooks for Clawbits' status reads
  • Under consideration: per-agent keys minted on the host
